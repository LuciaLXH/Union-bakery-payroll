# 本机试用版与后续更新

## 老板 Windows 试用包（2026-11-19）

老板版本采用 Windows 10/11 Intel/AMD 64 位便携包，包含 Python 3.13.17、PostgreSQL 18.7 和固定版本依赖，不要求老板安装 Python、Git 或 Docker。若电脑缺少微软 C++ 运行库，使用包内 `00-补充运行库.cmd` 从微软官方下载并安装，首次安装这一步需要网络。完整步骤见仓库 `packaging/windows/使用说明.txt`（也在 ZIP 根目录）。

解压后双击 `01-启动工资网站.cmd`，首次设置老板自己的密码（账号 `boss`）。网页仅绑定 `127.0.0.1:18512`，数据库仅绑定 `127.0.0.1:18532`。默认只含两名虚构员工，不连接正式数据库、不包含开发者凭据。AI 默认关闭；可通过 `04-设置千问AI.cmd` 配置老板自己的千问账号，需要联网。

程序目录可替换；数据、凭据、日志和备份独立保存在 `%LOCALAPPDATA%\UnionBakeryPayrollTrial`，按同一 Windows 用户使用。启动前和正常停止时自动备份。更新时停止旧版、解压新版、运行新版，继续使用原有数据目录；不要删除数据目录。数据库结构不兼容会停止，需另行提供迁移流程。备份需复制到另一块磁盘或老板控制的安全位置。

已验证本地完整测试 159 项通过；[Windows 自动验收](https://github.com/LuciaLXH/Union-bakery-payroll/actions/runs/44493594771)通过，使用包内的 Python 和 PostgreSQL 验证首次初始化、老板登录、通勤扣减后的试算金额 2943.90 元、重启数据保留、10 张表备份恢复一致、网页健康检查及停止协议。Windows 启动器修复位于 `57e3d68`。这不等于老板电脑已完成验收；首次试用还需检查双击启动、密码输入、浏览器、手动修改/保存计算、Excel 导出、停止后重启。首次运行库安装和老板具体杀毒软件尚未验证。

构建入口为 `scripts/build_windows_bundle.py`，仅复制允许的应用文件；运行时和依赖固定哈希，包内 `manifest.json` 记录文件及版本。构建示例（已准备官方运行时缓存和 Windows wheel 缓存时）：

```sh
.venv/bin/python -m scripts.build_windows_bundle --output .local/releases/windows-owner
```

完整 Windows 构建及测试流程在 `.github/workflows/windows-trial.yml`，只支持手动触发，不使用业务密钥、不部署到 Render。实际老板电脑验收后，再单独安排正式数据迁移；当前云端正式数据未改动。

## Mac 开发试用（保留）

本版先供当前 Mac 试用。网页和 PostgreSQL 均在本机，不连接 Render 或 Neon，也没有导入正式员工资料。它不是可直接发给其他电脑安装的独立安装包。

## 使用

1. 保持 Postgres.app 运行（本机 5432 端口）。当前机器已有项目 `.venv` 及依赖。
2. 双击项目目录的 `启动本地试用.command`，打开 http://127.0.0.1:18502 。
3. 首次创建独立数据库 `bakery_payroll_local_demo`，只含“示例小麦”“示例小豆”两名虚构员工。以后启动保留已有数据，不重新导入或覆盖。
4. 在启动终端按 Control+C 停止网页。再次启动后，已保存数据仍存在；未保存的输入不会保留。

手动录入、工资计算、历史、锁定及 Excel 导出均使用本机数据库。试用启动脚本清除继承的云端、正式环境和 AI 配置，当前没有启用 AI；以后启用千问仍需要网络与独立配置。默认页面可能停在 AI 识别入口，切换到“手动填写”即可试用。

网页只监听 127.0.0.1，同一电脑可以访问；手机和其他电脑暂不能访问。当前为无登录的开发试用模式，不用于保管正式工资。老板正式使用前需完成安装包、登录权限、备份安排和正式数据迁移。

## 数据与备份

程序文件在项目目录；数据库在 Postgres.app 管理的数据目录，独立于程序文件。更新程序不应删除或重建数据库。

双击 `备份本地试用.command`，备份保存在 `.local/local-demo/backups/日期时间/`，包含数据库归档和校验清单。整个备份目录需要一起保留；将来正式使用时应定期复制到另一块磁盘或老板控制的备份位置。本机备份无法防止整台电脑或硬盘损坏。

已验证：重复初始化不改变所有表内容；备份恢复到独立空库后，10 张表的内容与备份一致。恢复演练库已删除，试用库保留。

## 后续更新是否复杂

- 普通页面修复、AI 识别改进和兼容的计算修改：停止网页 → 备份 → 安装维护者验证过的新程序 → 启动。通常无需修改数据库内容。
- 新增数据库字段或表：维护者准备版本迁移脚本，先在副本验证，再在更新流程中备份并迁移。不能通过重新初始化数据库来升级。
- 更新失败：普通程序更新可在结构兼容时回退程序；涉及结构变化时，需同时遵循对应的数据库恢复方案，不能保证仅换回旧程序就能恢复。

当前没有自动更新器，也不会自动拉取 GitHub、改动依赖或升级数据库。Windows 包发现结构版本不匹配时启动会停止并提示维护者，避免误覆盖。老板已确认使用 Windows，见本文开头的试用包说明；手机访问暂未实现。

本地版交付后，维护者不能像现在部署云端那样直接替老板更新电脑；老板需要运行更新包，或安排一次远程协助。日常修复可以让老板只做“备份、更新、打开”，复杂度主要留给维护者。
