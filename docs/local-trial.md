# 本机试用版与后续更新

本版先供当前 Mac 试用。网页和 PostgreSQL 均在本机，不连接 Render 或 Neon，也没有导入正式员工资料。它不是可直接发给其他电脑安装的独立安装包。

## 使用

1. 保持 Postgres.app 运行（本机 5432 端口）。当前机器已有项目 `.venv` 及依赖。
2. 双击项目目录的 `启动本地试用.command`，打开 http://127.0.0.1:18502 。
3. 首次创建独立数据库 `bakery_payroll_local_demo`，只含“示例小麦”“示例小豆”两名虚构员工。以后启动保留已有数据，不重新导入或覆盖。
4. 在启动终端按 Control+C 停止网页。再次启动后，已保存数据仍存在；未保存的输入不会保留。

手动录入、工资计算、历史、锁定及 Excel 导出均使用本机数据库。试用启动脚本清除继承的云端、正式环境和 AI 配置，当前没有启用 AI；以后启用千问仍需要网络与独立配置。默认页面可能停在 AI 识别入口，切换到“手动填写”即可试用。

网页只监听 127.0.0.1，同一电脑可以访问；手机和其他电脑暂不能访问。当前为无登录的开发试用模式，不用于保管正式工资。老板正式使用前需完成安装包、登录权限、备份安排和正式数据迁移。

## 数据与备份

程序文件在项目目录；数据库在 Postgres.app 管理的数据目录，独立于程序文件。更新程序不应删除或重建数据库。

双击 `备份本地试用.command`，备份保存在 `.local/local-demo/backups/日期时间/`，包含数据库归档和校验清单。整个备份目录需要一起保留；将来正式使用时应定期复制到另一块磁盘或老板控制的备份位置。本机备份无法防止整台电脑或硬盘损坏。

已验证：重复初始化不改变所有表内容；备份恢复到独立空库后，10 张表的内容与备份一致。恢复演练库已删除，试用库保留。

## 后续更新是否复杂

- 普通页面修复、AI 识别改进和兼容的计算修改：停止网页 → 备份 → 安装维护者验证过的新程序 → 启动。通常无需修改数据库内容。
- 新增数据库字段或表：维护者准备版本迁移脚本，先在副本验证，再在更新流程中备份并迁移。不能通过重新初始化数据库来升级。
- 更新失败：普通程序更新可在结构兼容时回退程序；涉及结构变化时，需同时遵循对应的数据库恢复方案，不能保证仅换回旧程序就能恢复。

当前没有自动更新器，也不会自动拉取 GitHub、改动依赖或升级数据库。结构版本不匹配时启动会停止并提示维护者，避免误覆盖。老板电脑的 Windows/macOS、是否需要手机访问确认后，再制作相应的一键安装/更新包。

本地版交付后，维护者不能像现在部署云端那样直接替老板更新电脑；老板需要运行更新包，或安排一次远程协助。日常修复可以让老板只做“备份、更新、打开”，复杂度主要留给维护者。
