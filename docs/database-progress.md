## 已讲解的 SQL

用户已完成建库、四张表的创建和测试数据录入，并理解 SELECT、表别名 AS、JOIN 与 ON 的匹配条件。已讲解 INSERT SELECT 按列复制数据、RETURNING 展示写入结果、UPDATE SET WHERE 定向修改，以及省略 WHERE 会影响全表。

快照是独立保存的值，外键关系不会让金额自动同步。修改员工档案用于后续月份；纠正某月的金额需要修改该月草稿并重新核算。快照本身并不等于历史记录已锁定。

版本规则：新记录及现有记录从 1 开始；更新明细中的实际内容后自动加一（包括工资、考勤和工资条备注）；重复写入相同值不加一。修改 created_at 不影响版本。记录旧结果时保留当时输入的 JSONB 副本，故输入版本变化后旧结果仍可追溯。当前结果必须同时匹配输入版本和程序采用的公式版本；不能直接取最后一条结果就当作有效工资。输入版本机制从应用 003 开始，不会补出之前未记录的修改历史。

003 在独立随机 schema 中通过 4 项 PostgreSQL 集成测试：实际变化与重复更新、旧结果保留及过期、重复核算约束、错误合计及 NaN 拒绝。测试全部回滚，不改已有业务表或保留测试 schema。复跑方法：`TEST_DATABASE_URL='postgresql://localhost:5432/bakery_payroll_dev' .venv/bin/python -B -m unittest discover -s tests -p test_database_schema.py -v`。普通测试默认跳过这四项，避免未配置数据库时意外连接。
