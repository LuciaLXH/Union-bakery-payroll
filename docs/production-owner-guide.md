# 老板单人正式版：操作与维护说明

更新：2026-10-25。范围：老板本人维护档案、核算、确认与记录发放状态。
托管暂时保留 Render 免费实例，数据库使用独立 Neon 免费项目。
账号先由开发者持有，后续交接；当前不能声称开发者无法访问真实数据。

## 老板日常操作

1. 用专用账号和密码登录。首次使用先建立门店、员工档案，核对约定工资。
2. 月度工资选择月份，建立对应门店本月记录。只带入约定金额，考勤从零开始。
3. 默认 AI 录入，也可手动填写。建议记清员工、日期、事项、数量。
   - “小杨10月8日迟到10分钟”默认**新增**，加到已有迟到分钟数。
   - “小杨本月累计迟到10分钟”替换本月总数。
   - 同一事项只录一次；核对员工和写入前后数字，再确认写入。
4. 点击“保存并计算本月工资”，核对实发，下载 Excel。
5. 核对员工名单、金额和需另行处理的事项后，勾选确认，点击“确认并锁定本月工资”。
6. 完成系统外转账后，可勾选并点击“标记已发放”。这只是记录状态，不会转账或发邮件。

| 状态 | 能做什么 |
| --- | --- |
| 核算草稿 | 可手动/AI修改，修改后重新计算；导出注明未确认 |
| 已确认 | 工资、考勤、上限、名单锁定；可查看、下载或标记发放 |
| 已标记发放 | 继续锁定；表示老板记录已在系统外完成发放，不是银行凭证 |

需要更正时，在计算结果下展开“需要更正已确认的工资”，填写原因、勾选说明，再解除锁定。
旧确认信息和核算版本保留在核算历史中。更正后请重新核算、确认。
已发工资的更正**不会撤销转账**；应核对补发/追回差额，不能把整月工资再次转账。

登录有效期为4小时。到期请刷新并重新登录；未保存草稿可能丢失，因此应及时保存。
连续5次错误登录后暂停1分钟，重新打开网页或重启服务不会清除数据库中的限速记录。

## 本版范围与上线前核对

- 仍不自动计算报废扣款、奖励扣款、半天缺勤、月中入离职折算、跨店分摊；备注不扣款。
- 老板已说明的报废规则（成品面包售价一半、馅料/面头成本价）已记录，但尚未接入实发。
- 不包含 Excel 建档导入、工资条 PDF、邮件、晋升流程、上月对比及 Dashboard。
- 第一店、第一月先与现用 Excel 逐人对账。差异未解决前，不以网页作为唯一发薪依据。
- 确认锁定是保护操作结果，不表示系统替代业务验收。

## 三种环境

- 中文测试服务：现有测试口令、虚构数据，供新功能验证。
- 老板正式服务：独立账号、独立空数据库，不复制测试员工和历史工资。
- 英文公开演示：访客临时数据，仍独立，不连接正式数据库。

正式入口通过 `APP_MODE=production`、数据库内部环境标识和 `PRODUCTION_INSTANCE_ID` 三者校验。
测试/本地工作台误连正式库会拒绝访问；正式入口误连测试库、标识不匹配或使用管理员连接也会拒绝启动。
数据库管理员仍有维护能力，这些检查不能替代资源归属和权限交接。

## 配置与发布（维护者）

首次建库：创建独立项目和空数据库 `bakery_payroll_production`。只在维护机器上提供
`PRODUCTION_ADMIN_URL`（直连）及 `PRODUCTION_APP_PASSWORD`（至少24字符），执行：

```sh
.venv/bin/python -m scripts.production_database init --database bakery_payroll_production
.venv/bin/python -m scripts.create_owner_password
```

初始化脚本拒绝非空库；依次执行001–005，不带入样例。生成受限账号 `bakery_owner_app`，返回实例标识。
老板密码只经隐藏输入生成哈希；原始密码不放 Git、不放聊天、不放 Render 环境变量。
Render 正式服务使用 `render.production.yaml` 的设置，启动命令 `sh scripts/run_production.sh`：

| 环境变量 | 内容 |
| --- | --- |
| APP_MODE | production |
| DATABASE_URL | 正式库**受限账号**的连接，可用池化地址；不能用管理员地址 |
| PRODUCTION_INSTANCE_ID | 空库初始化返回的标识 |
| OWNER_USERNAME | 老板专用账号 |
| OWNER_PASSWORD_HASH | 密码生成脚本输出的哈希 |
| AI_ENTRY_PROVIDER | qwen |
| DASHSCOPE_API_KEY | 已授权的千问北京地域专用密钥 |
| AI_ENTRY_BUDGET_CNY | 30 |

密码修改：重新运行密码脚本，更新 Render 的哈希并部署。旧登录会话随之失效。
不提供公开注册、找回密码邮件或多角色权限；忘记密码由资源持有人重设。
AI 预算是**每个应用数据库**的月度估算限额，正式与测试环境各自计数；不是百炼账户总限额。
如共享同一 API Key，两个环境消费都会计入同一百炼账号。费用以百炼实际账单为准。

测试库升级到本版前，备份后用管理员直连执行：

```sh
.venv/bin/python -m scripts.production_database migrate-test --database bakery_payroll_test
```

需要环境变量 `CLOUD_ADMIN_URL`。该命令只升级测试库005，不重建库、不清空原数据；已执行时拒绝重复。
以后新增迁移采用新的编号文件；已有正式库不能再次执行初始化脚本。

## 备份与恢复

已提供全库 public schema 备份工具，包含门店、员工、月度输入、核算历史、AI事件、预算、确认与更正审计等表。
备份与指纹校验使用同一个 PostgreSQL 一致性快照；金额不会先转浮点数。
归档校验码用于发现损坏，不是加密或数字签名。备份目录权限700、文件600，仍应存入老板控制的加密存储。

需要与服务器版本相容的 `pg_dump`、`pg_restore`，设置 `PG_BIN` 或加入 PATH。
在维护机器安全配置 `BACKUP_DATABASE_URL`（管理员直连），执行：

```sh
.venv/bin/python -m scripts.backup_database backup --output .local/backups/本次唯一目录名
```

恢复演练使用**独立空库**，名称以 `bakery_restore_` 开头。设置 `RESTORE_DATABASE_URL` 后：

```sh
.venv/bin/python -m scripts.backup_database restore-check --archive .local/backups/本次唯一目录名
```

脚本拒绝非空目标和正式库名称，恢复后逐表比对行数与内容指纹。不要提供不可信的归档。
数据库角色/密码和 Render 配置不在备份里。真正切换到恢复库之前，需要重建受限账号权限、核对实例标识、验证登录与工资，并确认切换时间；不能仅改一个连接字符串就宣称恢复完成。

**当前为手动备份流程，没有自动定时备份或异地上传服务。** 初期由开发者负责：

- 每次正式工资确认后、任何结构迁移或发布前，做完整备份并核对成功。
- 老板同时保留已确认的 Excel 明细；它用于核对，不能代替数据库备份。
- 保留最近7份操作备份、每月确认后的归档；删除旧备份前检查仍有可恢复副本。
- 定期以及更改备份流程后重新做恢复演练。若需无人值守备份，应另行落实存储与调度。
- Render 免费实例会休眠、重启；数据库在 Neon，不能把 Render 本地文件当长期备份位置。
