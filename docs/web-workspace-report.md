## 完成内容

| 页面 | 现在可以完成的工作 |
|---|---|
| 月度工资 | 选择门店与月份、建立月度草稿、带入在职员工、编辑考勤及当月金额、保存考勤、核算并保存、设置月上限、下载有效结果 |
| 员工档案 | 建立门店、新增或更新员工、按姓名或编号搜索、维护岗位职级和常用金额、停用离职员工 |

页面采用统一侧栏、深绿色主色、灰白背景、卡片汇总和清晰的保存状态，临时产品名称为“麦序 · 工资”。隐藏与老板操作无关的开发者部署按钮。此版本继续使用 Streamlit，便于复用已验证的计算与数据访问代码。


## 日常使用流程

首次进入“员工档案”维护人员与常用金额。以后每个月：

1. 进入“月度工资”，选择门店、月份，点击“建立本月工资”。
2. 核对自动带入的名单；当月新建员工可在“名单与本月设置”中补入。
3. 在表格里填写考勤变化。右侧金额和备注项目可以横向滚动查看。普通缺勤、旷工不能重复计天。
4. 需要暂存时点击“保存考勤”；准备检查结果时点击“核算并保存”。
5. 必要时设置本月上限，核对实发合计，下载明细；历史页面可追溯每次已保存核算。

新月份带入员工档案里的当前约定金额，考勤从 0 开始。重复建立或补入员工不会重置已有考勤。修改档案的约定工资只影响以后新增的月度明细；本月调整应在当月表格中操作。入职时间晚于所选月份的员工不会带入；月中入职仍需人工核对金额。

已保存数据持久保存在 PostgreSQL。未保存的修改仅在当前网页会话保留，切换页面或月份可以返回继续，但不能依赖关闭浏览器后恢复未保存内容。

## 数据一致性处理

- “核算并保存”把输入更新和结果写入放在同一事务里，任一记录失败则本次全部回滚。
- 修改考勤或工资后，旧汇总和本月明细下载按钮失效；重新核算后才恢复。
- 保存前检查页面读取时的输入版本，阻止旧页面覆盖另一个操作刚保存的内容。员工档案及上限也检查是否已被其他操作更新。
- 重复保存相同输入与公式版本复用原结果，不制造重复核算历史。
- 金额核算复用现有 Decimal 引擎。历史页面展示当时已保存的输入和结果，不用当前档案或新公式重新计算旧工资。
- 月工资总额只统计当前输入与规则版本匹配的结果，不能把历史所有版本相加。全部已有明细核算完成才展示总额；名单是否录齐仍需人工确认。
- 达到或超过上限时提示暂无职级晋升空间。没有设置上限与明确设置 0 元是不同状态；低于上限不会自动批准晋升。

## 验证结果

**完整测试 61 项通过，无失败或跳过。** 包含原有 51 项和本次新增的 10 项工作台测试。新增测试覆盖：

- 新月份带入员工，重复建立不覆盖既有快照。
- 保存考勤并核算的原子性，异常工资整笔操作回滚。
- 旧页面不能覆盖新输入，员工资料变动不影响旧月度快照。
- 停用或未来入职员工不被带入。
- 工资上限未设置、0 元、并发修改；实发恰好等于上限、低于上限 0.01 元；未保存时不显示预算结论。
- 网页新增员工、建立月份、保存核算、切换历史页面、重新打开会话。
- 未保存修改和只保存未重算时，旧结果不能通过本月明细下载按钮导出。

## 当前边界与建议下一步

目前是可以本地使用和验收的工作台，尚不是正式上线版：没有登录权限、正式发薪确认锁定、完整操作审计、个人工资条、云端部署或备份恢复验证。职级字段可以维护，上限目前只提示，不会阻止档案页手工编辑职级；正式晋升执行需要独立业务流程。管理员直接操作数据库不受网页保护机制的完整约束。

已有 Excel 暂不支持一键批量建立永久员工档案；今后需要批量迁移时，应增加员工编号映射、预览和重复检查。离职生效日期、转店、首月折算和半天缺勤仍按原有边界处理。

建议先用 2–3 名虚构员工走完一个月份并体验布局，再完善个人工资条和确认锁定流程；之后推进云端测试、老板权限和备份方案。当前无需老板提供真实名单或工资数据。
