# 2026-11-02 AI 录入流程简化

## 范围

用户授权先完成流程简化，测试网站验证后更新正式网站。价格表导入、报损扣款仍未接入。本次无数据库结构迁移，也不修改工资公式。

原流程需要分别识别、预览、勾选、保存记录、再计算。新流程为“整理记录 → 核对记录与预计工资 → 确认以上记录并计算工资”；可选择“先保存，稍后计算”或取消。

## 实现

- 自动展示每条事项的业务含义、受影响员工的确认前后实发试算及差额、涉及门店全部当月员工的计算范围。报损和备注明确不扣款。比较基准是当前已保存输入的试算，不是上月工资。
- 后台先校验员工档案、月份状态、输入版本、规则版本和重复事项。保存与计算在同一事务完成，多店任一失败则整批回退，事件记录也不会残留。
- 保留仅保存入口；主操作完成后显示成功状态和下方计算结果，禁用重复提交。保留核对区域以减少页面高度突变；回调重验原文、月份和待提交的表格编辑。
- 未处理的同月 AI 草稿会阻止从下方直接计算或确认工资；手动仅保存仍允许，以便解决未保存修改冲突。
- 页面切换后保留当前会话选择的月份，避免查看历史后自动跳回当前月。测试显式选择样例月份，不再依赖系统日期为10月。

## 验证与发布记录

- 本地 PostgreSQL 隔离数据完整142项测试通过，无跳过（16.543秒）。包括混合请假/报损/迟到的计算与Excel明细、多店失败回退、负工资回退、重复提交、过期预览、手动录入、确认锁定、英文演示隔离。
- 浏览器3轮：直接确认并计算、先保存后计算、再次直接确认。最终迟到22分钟及扣款22元一致。考勤区域最多1个，确认操作滚动位置均未回到顶部。
- 两个中文环境发布前均生成10表一致性备份，私有归档保存在 `.local/production-backups/`。部署与线上验证结果完成后续记。
- 原始采购截图、报价表、密钥和备份不随应用发布。老板正式数据仅用于只读验证，不提交测试考勤。
