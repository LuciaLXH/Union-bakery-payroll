## 保存和失效机制

1. 根据门店和月份找到草稿，锁住月度记录；已确认月份直接拒绝保存。
2. 按编号顺序锁住所选员工明细，读取同一版本的工资、考勤和备注。
3. 同一明细、同一输入版本、同一规则版本已经有结果时，复用其编号和计算时间。
4. 否则调用现有计算引擎，把当时输入、副本中的门店与月份信息、规则版本、各项扣款和实发金额一起插入结果表。
5. 整批成功才提交。输入校验失败、负数实发或数据库写入失败都会回滚本批次的新写入。
6. 当前状态查询必须同时匹配 input_version 和 config.RULE_VERSION。旧结果继续保留，过期结果不显示为当前金额。

输入版本由已安装的数据库触发器维护，重复写入相同值不增加版本。修改备注也会更新版本，保证后续工资条能够使用更新后的说明。

## 测试结果

完整测试共 51 项，全部通过，没有跳过：原有 36 项、数据库结构 4 项、本次保存流程 11 项。

- 正常保存、重复保存返回同一结果编号及计算时间。
- 修改考勤后结果过期，重算保存新版本，旧输入和旧金额仍可读取。
- 修改员工当前约定工资不会改变当月工资快照。
- 更换公式版本后，旧规则结果不会被当作当前结果；新结果另存。
- 已确认月份拒绝保存，错误月份、员工编号和含 SQL 特殊字符的输入不会误读或写入其他记录。
- 两人批次中第二人出现负数实发，第一人已经写入的本次结果也回滚。
- 仅修改失误备注时，新结果仍不扣款，同时保存新的备注快照。
- 大金额计算的 Decimal 分位在数据库中保持准确。
- 两个连接同时保存同一员工，只生成一条结果。
- 核算过程中另一连接尝试修改考勤会等待行锁，不会把旧输入结果保存成新版本。
- CLI 的 save、status、history 已实际运行；代码差异格式检查通过。

普通测试使用未提交的随机 schema，结束回滚；并发测试为多连接可见性临时提交专用 schema，结束删除。最终查询确认遗留 payroll_test_ schema 数量为 0。

## 使用方式

在普通终端执行，保持 Postgres.app 运行：

```sh
cd '/Users/liuxiaohan/NZ-Jobseeking/2026 JOB/Projects/bakery_payroll'
source .venv/bin/activate
export DATABASE_URL='postgresql://localhost:5432/bakery_payroll_dev'
python -m scripts.database_payroll status --store '测试面包店' --month 2026-10 --employee DEMO-001
python -m scripts.database_payroll history --store '测试面包店' --month 2026-10 --employee DEMO-001
```

需要保存时，将 status 替换为 save。数据未改变时再次保存会复用版本 3 的结果。省略 --employee 表示处理该店当月所有已有明细，并不保证员工名单完整。

完整测试命令：

```sh
TEST_DATABASE_URL='postgresql://localhost:5432/bakery_payroll_dev' python -m unittest discover -s tests -v
```
