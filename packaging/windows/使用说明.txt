Union Bakery 工资管理 · Windows 试用包
状态：Windows 自动验收已通过；待老板电脑首次试用，暂勿录入正式员工工资。
适用：Windows 10/11，Intel/AMD 64位，同一 Windows 用户账号使用。

【第一次使用】
1. 将整个 ZIP 完整解压到较短的目录，例如 C:\UnionBakeryTrial。不要在压缩包内直接运行，不要只复制某个文件。
2. 双击“01-启动工资网站.cmd”。若提示缺少微软运行库，先运行“00-补充运行库.cmd”（这一步需要联网，可能需要管理员确认）。
3. 首次设置登录密码：至少16个字符，可以使用一段容易记住的话。账号固定为 boss。输入密码不显示字符，这是正常的。
4. 程序自动启动本机数据库并打开网页：http://127.0.0.1:18512 。若浏览器没打开，可以手动输入这个地址。
5. 页面内只有两名虚构员工。先试手动填写、保存计算、Excel 导出与重启后数据保留。
6. 使用期间保留启动窗口。结束时双击“02-停止工资网站.cmd”，或在启动窗口按 Ctrl+C，等待备份和数据库关闭完成。

【本地数据在哪里】
数据库、账号配置、日志、备份位于：
%LOCALAPPDATA%\UnionBakeryPayrollTrial
可把以上整行粘贴到资源管理器地址栏打开。
数据不在程序包里。删除或更换程序包不应删除此数据目录。
不要手工改 settings.json、database 文件，不要把运行中的 database 文件夹直接当作备份。
备份包含本机凭据和工资数据，请妥善保管，不要发到公开群或提交到 GitHub。

【备份】
正常启动前、正常停止时均自动备份。也可先停止网页，再双击“03-备份工资数据.cmd”。
备份在上述目录的 backups 子目录。请定期将整个备份目录复制到另一块磁盘或老板控制的安全备份位置；只存在这台电脑不能防止硬盘损坏。
恢复需要维护者核对版本并演练。本版没有会覆盖现有数据的“一键恢复”按钮。

【以后怎么更新】
1. 正常停止旧版（完成自动备份）。
2. 将维护者提供的新版解压到一个新目录，保留旧版目录。
3. 使用同一个 Windows 账号双击新版“01-启动工资网站.cmd”。新版会继续读取上述固定的数据目录，并在启动前备份。
4. 核对员工数、最近月份、工资金额和导出。不能同时启动新旧两个版本。
如果更新涉及数据库结构，必须使用维护者提供的配套迁移流程；本包发现结构版本不匹配会停止，不会清空重建。
本版不自动联网下载更新。数据库结构变化后，不保证只启动旧程序就能回退，需使用经过验证的恢复方案。

【AI 识别】
默认没有 API Key，不会带入开发者账号。手动填写、计算、导出不依赖 Render 或 Neon。
如需 AI：先停止网页，再双击“04-设置千问AI.cmd”，输入老板自己的千问 API Key。下次启动生效。
本包使用阿里云百炼“华北2（北京）”接口、qwen3.7-flash 模型。请在百炼控制台创建同地域的密钥；其他地域先联系维护者匹配配置。密钥填在本包的“04-设置千问AI”中。
配置步骤：02-停止工资网站 → 04-设置千问AI（粘贴完整密钥并回车）→ 01-启动工资网站。仅刷新浏览器不会重新载入密钥。
保存密钥不代表验证成功。先用一条简单的测试记录识别；失败时只截图新的错误提示，不要截图或转发密钥。
11月22日版会区分密钥验证失败（401）、权限/账户问题（403）、模型/接口问题（404）、限流/额度（429）、网络、证书和超时。不需要反复重装或删除数据。
AI 识别需要联网，并由千问账号承担费用；只在点击整理记录时调用。密钥只保存在此电脑受保护的配置文件中。

【范围与限制】
仅允许本机访问；手机和其他电脑暂不能访问。没有安装 Windows 自启服务；电脑休眠或关机后网页不可用。
此 ZIP 不含真实员工、工资、旧密码、云数据库连接、开发者 AI 密钥。
已在 Windows 自动测试环境运行本包，验证依赖、数据库初始化、登录、工资显示、重启保留数据、备份恢复、网页启动与正常停止；尚未在老板电脑上试用。
请先让维护者协助完成 Windows 首次验收。确认可用后，再单独规划正式数据迁移与老板资源交接，不能把本包直接当成已完成验收的正式系统。

【遇到错误】
先记下或截图窗口里的提示。不要反复删数据库重装。日志在本机数据目录的 logs 子目录。
若端口18512或18532已占用，程序会停止，不会连接或结束不属于它的服务。
