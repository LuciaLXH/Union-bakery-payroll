# 面包店多门店薪酬核算系统

本项目是一个专为拥有 3 家分店的面包店设计的轻量化月度薪酬核算工具。系统采用 Python + Streamlit 架构构建 MVP（最小可行性产品），前端核心交互依赖 `st.data_editor` 实现类似 Excel 的在线动态表格微调，无需复杂的长期数据库，月末通过导入/导出 Excel/CSV 触发计算。

---

## 1. 项目概述

*   **架构选型**: Python + Streamlit (MVP 架构)
*   **前端核心**: `st.data_editor`（支持在线动态表格微调）
*   **数据流向**: 无需复杂的长期数据库，月末通过导入/导出 Excel/CSV 触发计算。

---

## 2. 核心薪酬逻辑架构

最终实发工资计算公式如下：

$$
实发工资 = 基础底薪调整后 + 全勤 + 绩效 + 加班费 + 手动福利 - 报损扣款 - 投诉扣款
$$

---

## 3. 详细业务规则

### 3.1 人员分类与底薪
*   **职位分类**: 店长、前台、后厨、学徒。
*   **基础工资**: 不同职位对应不同的基础底薪标准。

### 3.2 社保状态判定与调整
根据社保状态对基本工资（底薪）进行调整：
*   **不上社保**: 基本工资正常发放。例如：店长底薪内已包含 600 元社保补贴，无需扣减。
*   **上社保**: 需要从基本工资中直接扣除大约 1000 元（具体金额按当月实际缴纳标准计算）。
*   **底薪调整公式**:
    *   不上社保：$基础底薪调整后 = 基础底薪$
    *   上社保：$基础底薪调整后 = 基础底薪 - 当月实际社保缴纳标准（约 1000 元）$

### 3.3 试用期管理
*   **试用期时长**: 通常不超过 1 个月。
*   **工资折算**:
    *   若员工中途提前转正，当月按全额底薪计算。
    *   若未转正，则根据试用期约定的比例折扣计算当月底薪（如 80%）。

### 3.4 考勤与加项（奖金、加班费）
*   **考勤规则**:
    *   **后厨**: 迟到情况由主管进行汇报与抽查。
    *   **前台**: 通常无迟到早退，按标准出勤考核。
*   **全勤奖**: 固定或浮动（例如：标准全勤奖 400 元/月）。
*   **绩效奖金**: 固定或浮动（例如：标准绩效奖金 600 元/月）。
*   **加班费（仅限后厨）**:
    *   **前置门槛**: 当月店铺的“平均人效”必须 **大于 1800 元/人/天**，否则加班费为 0。
    *   **平均人效定义**: $\text{平均人效} = \frac{\text{店铺当月总营业额}}{\text{店铺总人数} \times \text{当月天数}}$
    *   **计算公式**:
        $$
        加班费 = \frac{当月基本工资}{30 \text{天} \times 9 \text{小时}} \times 1.5 \times 加班小时数
        $$
        *(注：当不满足前置门槛时，加班费 = 0)*

### 3.5 减项计算 - 报损扣款（核心难点）
员工需承担店铺运营中的商品/材料报损。具体规则如下：

*   **责任划分规则**:
    1.  **明确责任人**: 由该责任人单独承担报损金额。
    2.  **责任人不明**: 由当班的所有人员平均分摊报损金额。
*   **物品类别折算规则**:
    *   **成品报损**: 员工承担售价的 **1/2 (50%)**。
    *   **半成品/原材料报损**: 员工按原材料原价的 **100%** 承担。
*   **学徒免责条款**:
    *   学徒员工单月累计报损次数在 **2 次以内（含 2 次）**，全额免除报损扣款（扣款为 0）。
    *   **一票否决条款**: 若学徒发生**单次**报损数额巨大（**单次超过 200 元**），则不再享受免责，全额按比例扣款。

### 3.6 投诉扣款与手动福利
*   **投诉扣款**: 允许老板或店长根据当月实际发生的客诉情况，手动输入扣款金额。
*   **手动福利**: 支持手动添加个别员工的特殊福利或津贴（如节日慰问等）。
